# Skill: arxiv-digest

> Собственный навык (не из хаба). Ежедневный смысловой дайджест новых публикаций
> arXiv по теме вибродиагностики и прогноза остаточного ресурса (RUL).
> Задание P2.

## Назначение (purpose)
Каждое утро находить новые статьи arXiv по заданным рубрикам, отбирать их
**по смыслу** (релевантность теме «vibration-based RUL / bearing fault
prognostics»), а не по точному совпадению ключевых слов, и присылать в Telegram
короткий дайджест: 3–7 работ с одной строкой «почему релевантно» и ссылкой.

## Когда включать (triggers)
- По расписанию: каждый день в 09:00 по времени сервера (cron, см. `../cron/arxiv-digest.yaml`).
- По команде в чате: сообщение, содержащее «дайджест arxiv» или «что нового по RUL».

## Входные параметры
- Рубрики arXiv: `cs.LG`, `eess.SP`.
- Тематический фокус (для смыслового отбора): остаточный ресурс (RUL),
  вибродиагностика, подшипники, fault prognostics, degradation modeling.
- Окно: статьи, добавленные/обновлённые за последние 24 часа.
- Порог релевантности: 0.6 (по оценке модели, 0–1).

## Что делать (процедура)
1. Запросить arXiv API:
   `http://export.arxiv.org/api/query?search_query=cat:cs.LG+OR+cat:eess.SP&sortBy=submittedDate&sortOrder=descending&max_results=60`
2. Распарсить Atom-ответ: title, authors, abstract, arXiv id, ссылка, дата.
   Отфильтровать по дате (последние 24 ч).
3. Для каждой статьи оценить смысловую релевантность теме (0–1) по abstract —
   это суждение модели, НЕ поиск по ключевым словам. Отбросить всё ниже порога 0.6.
4. Отсортировать по релевантности, взять топ-7.
5. Сформировать дайджест в формате результата (ниже).
6. Отправить в Telegram пользователю. Записать прогон в лог
   (`~/.hermes/logs/arxiv-digest/<дата>.md`): число найденных/отобранных,
   время выполнения, расход токенов.

## Формат результата
```
📚 arXiv-дайджест · {дата} · отобрано {k} из {n}
1. {Заголовок}
   {релевантность 0–1} · {почему релевантно — 1 строка}
   {ссылка на abstract}
...
Расход: {in_tokens} вход / {out_tokens} выход токенов · {время}s
```

## Обработка отказов (обязательно)
- **Источник недоступен** (arXiv API таймаут/5xx): НЕ выдумывать статьи.
  Сообщить: «⚠️ arXiv недоступен ({код/ошибка}), дайджест пропущен, повтор завтра».
  Один повтор через 5 минут, затем отказ.
- **Пустой результат** (за сутки нет релевантного): сообщить явно
  «За сутки новых релевантных работ не найдено» — это валидный результат, не ошибка.
- **Превышение лимита LLM (429)**: пауза 60 с, повтор с fallback-моделью; при
  повторном 429 — отложить прогон и уведомить пользователя, НЕ галлюцинировать оценки.
- **Сомнительная ссылка**: публиковать только arXiv id/URL из ответа API;
  никогда не конструировать URL «по памяти».

## Требуемые инструменты
`web_fetch` (arXiv API), LLM (смысловая оценка), `files` (лог), Telegram-шлюз.

## Замер (заполняется по прогонам, P2)
См. таблицу в `REPORT.md` → раздел P2 (время и токены на прогон, пересчёт в месяц).
